# Software Builder (Admin) Guide

This guide describes the **Software Builder**, an admin-exclusive system that integrates GitHub Issues with the Jules Agent to automate development tasks.

## Overview

The Software Builder (`/admin/github`) provides a Kanban interface to manage the software lifecycle:
1.  **Issue**: A bug or feature request is created in GitHub.
2.  **Plan**: Jules (the Agent) analyzes the issue and proposes a plan.
3.  **Code**: Upon approval, Jules writes code and creates a Pull Request.
4.  **Review**: The admin reviews and merges the PR.

## Prerequisites

To enable the Software Builder, the following environment variables must be set:

```bash
# GitHub Integration
GITHUB_TOKEN=ghp_...         # Personal Access Token with Repo scope
GITHUB_OWNER=YKDBontekoe    # Target Repository Owner
GITHUB_REPO=ai-book-world-builder # Target Repository Name

# Jules Agent Integration
JULES_API_KEY=AIza...       # API Key for Jules (Google)
```

## The Workflow

### 1. Backlog (GitHub Issues)
The **Backlog** column fetches open issues from the configured GitHub repository.
-   **Action**: Click the "Wrench" icon (Start Fix) on an issue card to assign it to Jules.
-   **Effect**: This creates a new **Jules Session** initialized with the issue's description.

### 2. In Progress (Jules Sessions)
The **In Progress** column displays active Jules Sessions.
-   **State**: Displays the agent's current state (e.g., `PLANNING`, `AWAITING_PLAN_APPROVAL`).
-   **Interaction**: Click a session card to open the **Jules Chat** interface.
    -   **Chat**: Converse with the agent to refine requirements.
    -   **Plan Review**: View and approve the implementation plan proposed by Jules.
    -   **Artifacts**: See diffs and file changes generated by the agent.

### 3. Review (Open PRs)
Once Jules completes a task, it opens a Pull Request. These appear in the **Review** column.
-   **Action**: Click to view PR details (handled via GitHub standard interface).

### 4. Done (Closed)
Shows recently closed issues and merged PRs.

## Security

-   **Admin Only**: All actions are protected by `requireAdmin` middleware. Only users with `role: 'admin'` in the database can access these endpoints.
-   **Server-Side**: GitHub tokens and API keys are never exposed to the client.

## Troubleshooting

> For advanced debugging and technical details, see the **[Jules Integration Guide](jules-integration.md)**.

-   **"Jules API Error"**: Verify `JULES_API_KEY` is valid and has quota.
-   **"GitHub Bad Credentials"**: Verify `GITHUB_TOKEN` has read/write access to the repo.
-   **Session Stuck**: If a session remains in `IN_PROGRESS` without updates, use the Chat interface to ask "Status?" or "Abort".
